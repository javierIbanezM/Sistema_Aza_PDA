# S3 (Simple Storage Service)

> Ver [`../../decisions/s3-vs-efs.md`](../../decisions/s3-vs-efs.md) para cuándo elegir S3 frente a un sistema de archivos compartido.

## Qué es: almacenamiento de objetos, no un sistema de archivos

Almacena objetos (archivos) identificados por clave dentro de un bucket, con durabilidad extremadamente alta (11 nueves) — apropiado para archivos estáticos, backups, data lakes, contenido servido a través de CDN. No es un sistema de archivos con semántica POSIX (sin bloqueos de archivo, sin edición parcial eficiente de archivos grandes).

## Clases de almacenamiento: coste según patrón de acceso

| Clase | Coste | Uso |
|---|---|---|
| Standard | Más alto | Acceso frecuente |
| Standard-IA / One Zone-IA | Medio | Acceso infrecuente pero rápido cuando se necesita |
| Glacier / Glacier Deep Archive | Muy bajo | Archivo a largo plazo, recuperación en horas, no inmediato |
| Intelligent-Tiering | Automático | Patrón de acceso desconocido/variable — AWS mueve entre clases automáticamente |

Lifecycle policies para transicionar objetos automáticamente entre clases según antigüedad (ej. mover a Glacier tras 90 días sin acceso) — evita pagar tarifa Standard indefinidamente por datos raramente accedidos.

## Seguridad: nunca bucket público por defecto

```json
{
  "Effect": "Deny",
  "Principal": "*",
  "Action": "s3:*",
  "Condition": { "Bool": { "aws:SecureTransport": "false" } }
}
```

"Block Public Access" habilitado a nivel de cuenta/bucket por defecto — un bucket accidentalmente público es una de las causas más comunes y más costosas de brechas de datos en AWS (ver `CLAUDE.md` sección 12). Acceso controlado explícitamente vía políticas de bucket/IAM, o URLs firmadas de tiempo limitado para acceso temporal controlado sin hacer el bucket público.

## Versionado y protección contra borrado accidental

```
Versionado habilitado + MFA Delete para buckets críticos
```

El versionado preserva versiones anteriores de un objeto ante sobrescritura/eliminación — combinado con MFA Delete (requiere autenticación multifactor para eliminar versiones permanentemente), protege contra borrado accidental o malicioso incluso con credenciales comprometidas.

## Cifrado en reposo y en tránsito

- **En tránsito**: forzar HTTPS (política de bucket que deniega `aws:SecureTransport: false`).
- **En reposo**: SSE-S3 (gestionado por AWS) por defecto, o SSE-KMS (ver [`../aws-security/kms.md`](../aws-security/kms.md)) cuando se necesita control granular de la clave de cifrado y auditoría de su uso.

## Checklist

- [ ] ¿"Block Public Access" está habilitado, con acceso controlado explícitamente vía política, no por bucket público?
- [ ] ¿Existen lifecycle policies que transicionan datos poco accedidos a clases más económicas?
- [ ] ¿El versionado está habilitado para buckets con datos críticos, con MFA Delete si el riesgo lo justifica?
- [ ] ¿Se fuerza HTTPS y se cifra en reposo, con SSE-KMS si se necesita auditoría del uso de la clave?
